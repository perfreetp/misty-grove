# AOI 焊点缺陷复判工作台

面向 PCB 产线 AOI 工站的焊点缺陷复判系统。检测机按批次吐出缺陷记录与对应板面图像，复判员在 PixiJS 画布上逐处复判、框选标注，单板提交后按缺陷类型阈值自动判定过站，批次经品质主管抽检后放行。

## 运行

```bash
npm install
npm run dev      # http://127.0.0.1:5173
npm run build    # 生产构建
```

数据保存在浏览器 localStorage（`aoi-recheck-db-v2`），「规则与留痕」页可一键重置演示数据。右上角可切换演示身份：复判员（张岚 / 陈昊）、品质主管（林静）、品质工程（周扬）。

## 业务流程

```
导入批次 → 待复判 → 复判中 → 待放行 → 已放行
                ↑                    │
                └──── 退回（填分类+原因，记录退回人）────┘
```

**复判台（画布）**
- PixiJS 画布，滚轮以光标为锚缩放，拖拽 / 空格 + 拖拽平移，`F` 适应窗口，`1:1` 实际像素。
- 检测机判点以琥珀色虚线框叠加显示，左侧列表可「采信」机器类型或一键判为「误报」。
- 框选模式（`B`）拖出缺陷范围，弹出类型选择（`1`–`5` 快捷键）；框内含机器判点会自动关联。
- 右侧实时按阈值计算本板判定与超阈值条目；`Delete` 删除选中标注，`V/H` 切模式。
- 底部胶片条快速切换同批其他板；提交后自动跳到下一块待复判板。

**判定规则**
- 各缺陷类型配置阈值，数量 **超过** 阈值即判返修。
- 连锡、偏移为硬性规则：阈值上限锁定 2 处，超过 2 处直接返修（配置只能更严格）。
- 「误报」不计入返修判定，只用于统计误报率。

**批次与放行**
- 单板提交自动汇总到批次；全批完成批次进入「待放行」。
- 放行仅品质主管可操作，且必须：全批复判完成 → 抽检样本 ≥ 5%（按板数向上取整）→ 逐块实际打开图像检视（系统记录检视时间）→ 填写放行意见。
- 退回需选分类 + 填原因（≥8 字），记录退回人与时间，批次回到「复判中」，全部单板重新复判。

**看板**
- 按检测程式 / 班次统计误报率、返修率、漏判申诉数。
- 误报率超过程式预警阈值的行标黄并提示「待调机」，列表与看板顶部横幅双重提醒。

**导出**
- 批次放行单（A4 HTML，含判定明细、抽检记录、签字栏）
- 缺陷分布图（SVG / PNG，客户交付版）
- 复判明细 CSV、程式质量统计 CSV

## 图像版本与标注留痕

- 每条标注挂在 **图像版本**（板号 + 版本号）上，不挂板。
- 换用重扫图像（「换图」）时：旧版本全部有效标注自动置为 **作废**，记录作废原因、操作人、时间；新版本从零开始，需重新复判。
- 只有当前有效版本的标注参与过站判定与看板统计；历史版本可只读比对，界面上以灰色虚线框 + 「作废」标签展示。
- 批次详情 / 设置页可查看完整审计流水（标注增删、换图、撤回、抽检、放行、退回、阈值变更）；已放行批次全站只读。

## 代码结构

```
src/
  types.ts              领域模型（批次 / 单板 / 图像版本 / 标注 / 缺陷记录）
  data/seed.ts          演示数据生成（确定性 PRNG，缺陷记录含真实形貌与漏判）
  lib/boardImage.ts     Canvas 程序化生成 PCB 板面图像（焊点形貌随缺陷类型变化）
  lib/verdict.ts        阈值判定与抽检比例计算
  lib/stats.ts          看板统计口径
  lib/export.ts         放行单 / 分布图 / CSV 导出
  viewer/PixiViewer.ts  PixiJS 画布：缩放平移、框选、标注渲染、机器判点叠加
  store/useStore.ts     状态与业务动作（zustand + persist）
  pages/                批次列表、批次详情、复判台、质量看板、规则与留痕
```

板面图像在运行时由 Canvas 程序化绘制（PixiJS `CanvasSource` 转纹理），因此无需外部图片资源；每块板、每个图像版本的曝光、噪声、焊点形貌均由种子确定性生成，刷新后可复现。
